# Dez v0.0.4 external sessions

This is the active v0.0.4 execution plan. [Fork Notes](./fork-notes.md) remain
the permanent source of truth. v0.0.3 evidence remains valid only for the exact
source and artifacts it measured.

## Release promise

A developer can open a codebase, run or reattach a terminal-native agent in the
native Main Work Area, understand its state from Projects, and review its
changes through Files, Git, diagnostics, and diffs without juggling competing
sidebars or losing process ownership.

The shell has three owners:

| Region              | Owns                                                                  |
| ------------------- | --------------------------------------------------------------------- |
| **Projects**        | Global codebase navigation and low-noise Session/attention projection |
| **Main Work Area**  | Draggable files, terminals, diffs, searches, settings, and reviews    |
| **Workspace Tools** | One contextual Files, Outline, Git, Debug, or Built-in Agent surface  |

External terminal tools do not add a fourth region.

## Ownership contract

| Source                       | Authority                           | Dez behavior                                                          |
| ---------------------------- | ----------------------------------- | --------------------------------------------------------------------- |
| Dez interactive terminal     | `dez-terminal-host` when packaged   | Create, detach, restore, and end through the Host contract            |
| tmux session                 | tmux server                         | Discover and attach as a client; never claim or terminate the session |
| Herdr pane                   | Herdr server and socket             | Discover and attach without automatic takeover                        |
| Other local terminal process | Owning terminal application and PTY | Show a bounded, ephemeral, read-only observation                      |

Closing a tmux or Herdr terminal tab detaches that client. Closing Dez must not
end externally owned work. **End Terminal** applies only where Dez owns the
process lifecycle.

## UI recovery plan — evidence from the 2026-07-29 runtime audit

The runtime screenshots are a regression list, not a visual target.

1. **Projects is a navigator, not a terminal inventory.** Project rows own
   attached agent Sessions and attention. Attachable tmux/Herdr work remains
   compact. Ordinary PTYs stay behind an explicit disclosure.
2. **One project cannot inherit another project's Session.** A restored
   terminal without a matching open root must remain detached secondary
   activity; it must never appear beneath `Empty Workspace`.
3. **Home is a start surface, not documentation.** Keep one strong
   **Open Workspace** action, Clone as secondary, recent codebases, and one
   short Run → Supervise → Review explanation. Remove ornamental empty space.
4. **Menus expose user jobs.** Everyday Project menus contain Run, Files,
   Review, and a short layout chooser. Saved-layout administration belongs in
   commands/settings.
5. **Native tabs remain the only document navigation.** Drag, reorder, preview
   replacement, split, close, Back, and Forward must use the existing Zed
   workspace model. Dez does not draw a second browser-style tab strip.
6. **Lumin is material, not decoration.** Window translucency is limited to
   shell/chrome surfaces; editor and terminal content retain contrast.
   Separators, hover, selection, and focus must remain visible in dark, light,
   and reduced-transparency modes.
7. **No product overlays.** Persistent mascots, floating task bubbles, and
   screen-edge controls are not Dez UI and must not be introduced. Native
   notices remain bounded to their owning surface.

The work is accepted only through the viewport and appearance matrix in
Milestone 4, followed by an exact-artifact cold-start and recovery smoke test.

## Deferred

The release does not include embedded Live Preview, remote Herdr discovery,
tmux control-mode event streaming, arbitrary PTY adoption, automation
dashboards, another task system, cross-device continuity, or a custom tab/pane
implementation.

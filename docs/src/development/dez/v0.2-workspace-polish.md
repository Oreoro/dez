# Dez v0.2 Workspace polish

This is the active v0.2.2 source candidate after the v0.1 hardening baseline.
It does not claim that a signed v0.2 binary has shipped. [Fork
Notes](./fork-notes.md) remain the permanent product and architecture source
of truth. The [Native Surface Contract](./surface-contract.md) is the detailed
wireframe, surface inventory, and interaction reference for this work.

## Product promise

Dez should feel like one native Workspace, not a terminal dashboard layered
over an editor:

```text
Open Workspace
-> start or continue work in native terminal tabs
-> supervise Sessions and attention in Workspaces
-> inspect with Files, tasks, diagnostics, and Debug
-> Review Changes in the Main Work Area
```

The visible navigation story uses four destinations: **Home** starts or
resumes context, **Main Work Area** owns the work, **Workspaces**
switches and supervises, and **Review Changes** verifies the result. Labels on
native Home, Add, Settings, terminal details, and the navigator use that same
grammar.

## Workspace contract

- One Main Work Area owns every ordinary surface through Zed's native tab and
  pane model.
- Files, Git, Debug, and Built-in Agent are destinations in that tab strip,
  not permanent columns.
- Applying a destination layout consolidates existing populated work areas
  into tabs. It never hides or discards their content.
- Split Work Area is the only public workflow that may retain multiple
  populated work areas.
- Workspaces is optional, Workspace-first navigation. It starts closed and uses
  one header, one search affordance, and one options menu. Search becomes
  available when there are multiple Workspaces or sessions to navigate, and
  labels the surface as Workspaces rather than exposing the internal session
  implementation. Routine state adds no inventory caption; search, restoration,
  and attention add one compact inline status label. Search counts matching
  Workspace rows together with matching Sessions and terminals.
- When useful, Workspaces starts with a collapsible **Open Tabs & Tools**
  projection of the native Main Work Area tabs. It includes Home, code, diffs,
  terminals, and Workspace tools while Sessions stays activity-only. It stays hidden for a lone tab, a single pane
  stays flat, and actual splits receive compact pane group labels. Rows activate the existing native
  item and read its icon, disambiguated title, active state, and dirty state.
  Terminal rows retain task, Agent provider, or tmux identity. Built-in and
  external Agent tabs retain the same Dez or provider mark used by their
  native tab, and the projection exposes positional list semantics to
  assistive navigation. In a split layout, every pane's visible tab receives a
  quiet selected row; the focused pane retains the stronger accent icon while
  background tabs remain muted. The collapsed summary names both tab and pane
  counts, while the expanded group header quietly names the focused pane.
  The projection never owns a second tab model or duplicates tab close and
  drag behavior.
- Command Palette groups Workspace navigation under **Workspaces** and selected
  session lifecycle actions under **Agent Sessions**. Internal sidebar and
  thread type names do not become product navigation labels.
- Workspace and terminal recovery share one bounded, accessible
  **Workspace notices** region in Workspaces.
- Workspaces status remains Workspace-first when tmux, Herdr, or cmux activity
  is discovered. Path-matched activity appears beneath the most specific open
  Workspace. Pathless activity and sessions outside open roots remain reachable
  under **Other Running Sessions**; unrelated machine terminals never enter
  the navigator.
- Dez does not initialize the legacy machine-wide TTY observer. It therefore
  does not poll `/bin/ps` for a surface the product neither displays nor owns.
- Workspaces search, scope controls, utilities, empty states, and recovery
  actions use the same Workspaces and Workspace vocabulary in visible and
  accessibility labels.
- Multi-root Workspace headers use the first root plus a bounded root count.
  Every root remains searchable, and the full root list remains available in
  the header tooltip and accessibility label.
- Overview counts name the item they count. Agent provider and lifecycle state
  occupy ThreadItem's secondary metadata row, never the terminal or Session
  title line.
- Built-in Agent and Subagent surfaces use related Dez-native identity glyphs.
  Recognized terminal agents retain provider glyphs, and Workspaces presents
  lifecycle state without replacing identity. Subagents remain scoped to the
  parent Session instead of appearing as duplicate top-level rows. Each
  Subagent card names its current state to assistive navigation and advertises
  preview interaction only when that card has content to expand.
- Dez keeps that native secondary metadata row available at its supported
  Workspaces widths. It shows authoritative provider, lifecycle, worktree or
  working-directory, and attention data instead of collapsing those fields
  into the primary title.
- cmux listening ports use compact, muted trailing metadata: the first port and
  remaining count stay visible while the richer bounded list remains in the
  native tooltip and accessibility label. Passive port metadata never competes
  with the row title or adopts an action accent.
- The bottom native status bar remains visible and owns persistent editor
  state. A terminal context strip appears only for actionable state: an agent
  or task is running, Git changes are ready to review, the terminal has ended
  or failed, or no Workspace is connected. Terminal lifecycle remains
  authoritative: failed, exited, completed, unavailable, and unknown sessions
  name that state even if foreground-process observation is briefly stale.
  When Workspaces is closed, its fixed status-bar control remains visibly
  labeled **Workspaces** instead of becoming an unexplained sidebar glyph.
  Pending attention is announced to assistive navigation and colors the
  side-aware icon; the native tooltip names the **Open Workspaces** action.
- The native terminal tab owns the terminal title. Shell-emitted breadcrumbs
  remain available as an opt-in setting, but start off to avoid a duplicate
  title row.
- Terminal Details expands as an inline disclosure beneath the actionable
  terminal context strip. It does not cover the TUI with a popover or create a
  permanent inspector column. Collapsing it returns every pixel to terminal
  output while retaining the same native tab and process.
- Dez Settings begin with **Workspaces & Terminals**, **Agents**,
  **Appearance**, and **Workspace & Privacy** before inherited editor
  customization. A native **Default Terminal** dropdown lives under **Workspaces & Terminals →
  Terminal Launch** because it controls the Workspace terminal entry point.
  It offers the supported shell, agent, and tmux presets, reveals the raw field
  only for **Custom Command**, and preserves legacy command-only settings;
  explicit agent launchers remain per-launch actions.
  The dropdown gives every preset its resolved provider or tmux mark and keeps
  the selected-state check in a separate trailing slot. That launcher mark is
  shared by Home, the empty Main Work Area, pane `+`, and Workspaces. The empty
  Main Work Area also names its resolved destination as **Open Terminal ·
  Native Shell**, **Open Terminal · Codex**, or the equivalent provider, tmux,
  or custom-command label. Provider
  and tmux identity survives env/exec wrappers and absolute paths; shell and
  unknown custom commands retain the terminal mark.
  Compatibility controls for removed Session Rail chrome stay out of the
  graphical Settings surface.
- Settings action rows use outcome-specific native marks. Appearance recovery
  uses reset, keymap actions use keyboard or reference marks, and in-app tests
  use run. The external arrow is reserved for the cmux API guide so users can
  distinguish a documentation handoff from an action that changes Dez or cmux.
- Appearance starts with one scoped **Restore Native Dez Appearance** action.
  Navigation & Layout exposes the native status-bar visibility preference, so
  imported settings cannot leave users without a graphical recovery route.
- MCP and external-agent configuration resolve through the Settings window's
  active Workspace. Retained background Workspaces never receive a hidden
  configuration modal or silently supply the stores shown in Settings.
- First run uses Home and ordinary native tabs. It does not open a mascot,
  overlay, floating coach mark, or duplicate onboarding surface.
- Home starts at the Main Work Area edge and states the product loop in one
  sentence. It does not persist a step diagram or provider promotion beneath
  the launcher.
- Active Home names the complete run or edit → Workspaces attention
  → review loop without turning those steps into a second navigation surface.
- Home says **Continue your work** in both states and uses a flat heading
  without a decorative hero badge. Without a Workspace, it exposes Open
  Workspace, Clone Repository, and Recent Workspaces. With one open, **Start
  with a tool** exposes the default terminal, Codex, Claude Code, OpenCode,
  Workspace tmux, and the local cmux handoff; **Inspect and resume** exposes
  running Sessions, Files, and Review Changes. Quiet outcome metadata distinguishes each route at
  normal widths; compact Home hides that secondary text while retaining it in
  tooltips and accessibility descriptions. New File remains in File, the
  native `+`, and keyboard shortcuts.
- The true-empty Workspaces state uses one sentence to connect the codebase,
  terminals, Agent Sessions, files, and review to the Main Work Area. Its sole
  **Open Workspace** route uses the native primary-action treatment; no second
  launcher, card, or walkthrough competes with it.
- Once a codebase is open, its active Workspace header keeps the native terminal
  menu visible even before a Session exists. Inactive empty Workspaces use one
  labeled **Open Terminal** row, so every launch remains visibly scoped without
  duplicating controls.
- Workspaces does not inject import promotions into ordinary navigation.
  Importing compatible Agent Sessions remains an explicit action in native
  Agent History.
- Help opens that same native Home surface as **Open Home**.

## Acceptance gates

- [x] The final native-tool wireframe covers Files, Search, Workspace
  Diagnostics, Tasks, Debug, recent Workspace recovery, external browser/cmux
  handoff, and legacy-terminal ownership.
- [x] Workspaces projects open tabs and tools across real panes while panes keep
  order, selection, close, drag, preview, and split ownership.
- [x] Workspace Diagnostics exposes a keyboard-reachable Refresh action in its
  healthy empty state, and every icon-only toolbar action has an accessible
  label.
- [x] The Dez Task picker distinguishes loading, no saved tasks, and unmatched
  command input and uses Run Task / Run Command product language.
- [x] Documentation states that URLs use the system browser and cmux owns its
  own browser, tabs, splits, hooks, and action registry.

- No startup or restored layout creates an unexplained second pane.
- Back, Forward, Add, Switch Tab, close, drag, split, and status-bar controls
  remain keyboard reachable and use native Zed actions.
- A Workspace header restores that Workspace's last active tab and pane;
  **View → Navigate Workspaces** exposes Focus, Search, Previous, and Next.
  Search opens a closed Workspaces navigator and focuses the same native filter
  used by its header control.
- The Workspaces ellipsis menu mirrors Search and Previous/Next only when more
  than one searchable item or Workspace exists; routine single-Workspace work
  does not gain permanent navigation noise.
- **Open Tabs & Tools** mirrors every native surface owned by the active
  Workspace—Home, code, diffs, terminals, Files, Git, and other tools—while
  **Sessions** remains limited to running terminal and agent activity. A
  single-pane Workspace stays flat; Pane labels appear only after an intentional
  split.
- Home is headed **Continue your work** in both states. Without a Workspace it
  offers only Open Workspace, Clone Repository, and Recent Workspaces. With a
  Workspace it separates direct terminal/agent/tmux/cmux launchers under
  **Start with a tool** from running-session, Files, and review routes under
  **Inspect and resume**.
- Settings can restore the Dez visual profile without resetting font sizes or
  unrelated preferences, and can show a previously hidden native status bar
  without requiring JSON editing.
- Every native Main Work Area pane keeps an accessible `+` immediately after
  its tabs. The menu reopens Home, opens Recent Workspaces, terminals, files,
  and Workspace tools through existing Zed actions; its terminal submenu
  includes Default Terminal, Native Shell, **Workspace tmux**, Codex, Claude
  Code, and OpenCode routes. **Continue Agent** provides the providers'
  documented last-session commands. **Browse Running Sessions…** and the explicit
  cmux handoff follow those native routes. Dez's File menu exposes the same routes in the same order, but
  its first row previews the configured result as **Default · Native Shell**,
  **Default · Codex**, **Default · Claude Code**, **Default · OpenCode**, or
  **Default · Custom Command**. Neither path creates a second tab or pane
  system. **Workspace tmux** is the contextual launch label; **tmux Session**
  remains the reusable Default Terminal preset label. The Add menu also exposes
  the inherited native task launcher beside Files, Review Changes, and Debug.
  Its Built-in Agent row and the matching Workspace Options row open that
  native surface only when an authenticated default model makes it usable;
  otherwise both become **Configure Built-in Agent…**, use the Settings mark,
  and open provider settings instead of a dead model-less surface.
- The Add menu is work-first: terminal and Agent launch routes lead, running
  tmux, Herdr, and cmux handoffs follow, files and review remain together, and
  Home or Recent Workspaces stay at the end as secondary navigation.
- When a pane's tabs overflow, **Switch Tab** opens **Tabs in This Pane** and
  preserves modified and pinned state in each native menu row. It remains a
  switcher for the owning pane rather than a second global tab model.
- A truly empty Workspaces activity list presents **Open Terminal** as its one
  primary action. A zero-result filter presents **Clear Search** with the same
  recovery emphasis; the positive caught-up state keeps **Show All** outlined
  so it does not compete with active work.
- Native Close, Unpin, and read-only controls use the owning item identity.
  Their focus, hover, and activation state cannot collide with sibling tabs in
  the same pane.
- Agent change review keeps Previous/Next Change, file-level Review/Reject/Keep,
  and whole-review **Reject All Changes** / **Keep All Changes** in the owning
  native surface and keyboard tab order. The Built-in Agent Edits disclosure
  announces expanded state and changed-file count, responds to Enter and Space,
  and exposes **Review Changes** as its visible primary inspection action.
- Git History loading uses a status label and spinner. A completed failed graph
  request exposes one native **Retry** action that invalidates only that failed
  request before loading again; missing-repository and no-commit states remain
  truthful, quiet, and actionless.
- A Subagent card keeps state in text, presents stopping and previewing as
  distinct controls, and renders **Open Subagent Session** as an outlined,
  keyboard-reachable handoff to the exact existing child Session.
- The Add menu uses outcome-oriented copy: **Default Terminal**, **Native
  Shell**, **Find File…**, and **Review Changes**. Terminal Details uses a
  compact **Workflow** section instead of repeating onboarding copy.
- The native tab strip and its `+` remain visible when Home or an empty
  Workspace is the only Main Work Area content.
- Terminal launch failure stays edge-anchored inside its native tab, renders no
  fake shell prompt, starts no replacement process, and exposes **Edit Terminal
  Settings** as its one primary action. That action deep-links to
  `agent.terminal_launcher`; the split-menu alternative still opens raw
  `settings.json` for expert recovery.
- The optional navigator on the configured window edge leads with flat native
  Workspace rows. Each row switches the active Workspace, shows live Git branch
  and changed-file metadata when available, and expands only the agent sessions
  associated with that Workspace. Git association is path-component aware and
  works when a Workspace root equals, contains, or sits inside a discovered
  repository; multi-root summaries deduplicate repository work directories.
  The two-line title and Git stack owns only the flexible row width and
  truncates before disclosure, attention, terminal, or options controls. A
  single tooltip and accessibility description retain the complete root and
  Git summary. It is not a second Files tree or terminal renderer.
- The optional **Open Tabs & Tools** section appears for two or more active
  native pane tabs, stays flat with one pane, groups only real splits, activates the exact owning
  item, shows the visible tab in every split while distinguishing the focused
  pane in both the group header and row treatment, reports pane count while
  collapsed, persists its disclosure state, and yields its space while
  Workspace search is active.
- A two-root Workspace has one bounded visible title such as
  **compiler · 2 roots**. Searching for either root finds it, and a narrow agent
  row never places provider or lifecycle text beside its primary title.
- The navigator header exposes one keyboard-accessible `+` that uses Zed's
  same-window **Open Workspace** action. It does not create an empty project
  card or bypass native workspace restoration.
- Opening Workspaces never inserts a promotional banner above or below the
  Workspace list. Agent History retains the discoverable import control.
- Opening or hiding Workspaces does not start a background inventory of
  unrelated applications. Only explicit tmux, Herdr, and cmux integrations use
  their documented discovery interfaces.
- tmux, Herdr, and cmux discovery results reconcile independently. A transient
  failure preserves and labels only that source's rows as **last known**; a
  successful empty result removes them and successful peer integrations
  continue updating. Every launched source command is kill-on-drop. tmux and
  cmux scans have source-wide bounds. Herdr endpoint queries have individual
  bounds, with at most eight queries in flight, and the complete Herdr source
  scan—including executable discovery—shares one four-second deadline. Results
  completed before that deadline are preserved while unfinished endpoints
  become failures. One unresponsive integration or Herdr endpoint therefore
  cannot stall the Workspace navigator indefinitely or hide healthy peer
  results.
- Each integration exposes one distinct source state: **Missing** when its
  executable is unavailable, **Empty** after an authoritative successful scan
  with no sessions, **Failed** when discovery does not complete, and **Ready**
  when current sessions were returned. Workspace-specific empty copy must not
  collapse these states into “no sessions.”
- Each current external item is projected beneath the most specific matching
  Workspace. Items without a current working directory or outside all open
  roots are placed in **Other Running Sessions**. Arbitrary Terminal.app,
  iTerm, Warp, or IDE PTYs remain absent.
- **Browse Running Sessions…** switches to the Workspaces list, clears
  transient search, scope, and attention filters, expands groups that own
  discovered activity, requests a fresh scan, and focuses the navigator.
- A tmux exit code alone never means “no sessions”; only canonical missing-server
  output is authoritative. Herdr registry and snapshot failures also preserve
  last-known rows instead of silently collapsing to an empty source. Registry
  discovery uses `herdr session list --json`, so alternate Herdr/XDG locations
  do not depend on guessed filesystem paths.
- The explicit cmux handoff has its own eight-second deadline. Timeout or
  launch failure leaves the native Workspace unchanged and resolves the
  progress notice with a persistent native recovery action. Missing installs
  link to cmux; failures and timeouts link to the cmux API guide. Success remains
  an auto-hiding confirmation.
- A last-known external row refreshes its source before any attach. Retry looks
  up the current session by stable ID, reports when the session ended, and
  treats a missing terminal provider as an explicit attach failure.
- Host connection, reconnection, and command cycles remain bounded. An
  uncertain command is never replayed, and queued work behind a transport
  failure is rejected as stale. The GUI groups every frame-safe chunk for one
  input batch into one queue item, so queue admission accepts or rejects the
  batch as a unit. This admission atomicity does not guarantee end-to-end
  delivery: after transport or helper processing begins, a later failure can
  leave a prefix delivered. Dez treats that outcome as uncertain, logs the
  transport failure, and never replays it. The GUI rejects a batch above
  the helper's four-mebibyte PTY budget and applies a sixteen-mebibyte aggregate
  queued-input cap; the helper independently bounds its own queued input by
  message count and bytes. Admission saturation produces visible terminal
  backpressure, and the helper routes resize and termination through its
  separate PTY control channel.
- Ports remain absent until an authoritative Workspace-scoped local-server
  source is connected. Workspaces never scrapes terminal output or guesses
  port ownership from process names.
- Installing or configuring an MCP extension opens configuration only in the
  active Workspace. Switching Workspaces before opening Settings changes the
  Workspace-scoped MCP and external-agent stores Settings presents.
- A clean active terminal in a connected Workspace has no duplicate metadata
  toolbar above it.
- Workspace destinations preserve all open files, terminals, diffs, and tools
  as tabs when returning to one work area.
- Source identity, product copy, settings grouping, and public documentation
  use Dez and Workspace vocabulary consistently.
- Runtime, visual, accessibility, restart, permission, and packaging evidence
  must come from the exact candidate commit before release.

## Protected folders and release identity

An app bundle outside `/Applications` opens native Home but does not restore a
Workspace, start a terminal Host, or create a durable terminal. Home keeps the
stable **Continue your work** identity and exposes one inline **Install Dez to
continue** callout with **Install and Relaunch**. Workspaces says that no
Workspace has restored but does not duplicate the primary action or show false
branch, agent, port, or permission evidence. There is no startup dialog,
prompt, modal, overlay, silent continuation, or remembered bypass.

macOS still controls `Documents`, `Desktop`, and other protected locations. An
installed Dez preflights each restored Workspace root once. A denial becomes
one native **Workspace access required** state and **Grant Access…** action
before Git, search, LSP, agents, or terminals start. The action validates one
exact blocked folder without opening or replacing the current Workspace. A
successfully granted root leaves that state immediately without hiding any
other denied roots; relaunch or **Open Recent Workspaces…** retries restoration
if needed. Search cancellation participates in app quit, and repeated per-file
permission diagnostics collapse to one message per root.

The remote packaging workflow has separate Preview and Stable policy. Preview
uses the `Dez Preview` bundle identity and may be ad-hoc signed; its manifest
states that it is not a v0.2 release. Stable fails before the optimized
application build when any Developer ID or notarization credential is missing,
then requires a Developer ID Application authority, TeamIdentifier, Gatekeeper
assessment, and stapled notarization ticket before upload.

## Selective upstream adoption

Dez does not merge upstream `main` wholesale during product-polish work.
Relevant fixes are reviewed against the fork's Workspace and terminal
ownership contracts:

- Zed `23cb8712ba` retains a strong pane entity for the full async save
  operation. Dez adopts this to prevent a suspended save from failing because
  its pane was released.
- Zed `d23aaeebea` calls editor-local lock controls **Tab** controls rather
  than implying they change filesystem permissions.
- Zed `104ccf4bb6` routes shell-driven agent-terminal close requests through
  the navigator's ownership path, so the remaining terminal becomes active
  instead of leaving an uninitialized agent surface.
- Zed `f9a5bf9181` routes extension-provided MCP configuration through the
  active application window and its active Workspace. A retained background
  Workspace can no longer receive an invisible configuration modal.
- Zed `933c85b134` resolves MCP and external-agent stores from the Settings
  window's active Workspace project rather than the first retained Workspace
  or an empty launchpad. Custom-agent setup follows that same active Workspace.

The targeted source patches keep Dez's adjacent tab action, Workspace
navigator, terminal host ownership, and restoration logic intact. They still
require exact-candidate runtime evidence before release.

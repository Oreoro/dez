# Dez v0.5 surface readiness

This is the active source-readiness plan for Dez v0.5. It builds on the
0.4.0 source candidate and its exact-artifact evidence without claiming that a
v0.5 package exists, passes runtime validation, or is ready for promotion.
[Fork Notes](./fork-notes.md) remain the permanent product and architecture
authority. The [Native Surface Contract](./surface-contract.md) remains the
authoritative interaction and ownership specification.

## Release promise

> Open a Workspace, start or resume terminal-native work, supervise only what
> needs attention, use the complete native editor toolset, and return after a
> restart without reconstructing context.

The primary loop is one native journey:

```text
Open Workspace
-> start or resume work in a native tab
-> supervise bounded Activity in Workspaces
-> inspect Files, Search, Diagnostics, Debug, Git, and diffs
-> review and continue with Workspace and process ownership intact
```

Dez v0.5 is a complete Workspace-first development environment with a sharp
terminal-agent supervision wedge. It is not a terminal dashboard, chat shell,
custom tab implementation, multiplexer clone, or visual wrapper around Zed.

## v0.5 product boundary

The hierarchy is fixed:

> **Workspace is identity. Pane is target. Tab is content. Activity is signal.**

| Surface | v0.5 job | Native owner | Release requirement |
| --- | --- | --- | --- |
| Home | start or resume the product loop | closeable Main Work Area tab | one primary Workspace action; state-aware tool launch; no overlay |
| Workspaces | switch codebases and supervise current work | `MultiWorkspace`, `Workspace`, and owning stores | bounded Activity, activation-only Layout, truthful recovery, no duplicate tab state |
| Main Work Area | own editing, tools, terminals, review, and splits | native pane and tab model | selected tab, adjacent `+`, Back/Forward, overflow, split, drag, close, preview, and focus remain native |
| Status bar | preserve durable context and the Workspaces recovery route | native status items | one line; responsive identity; no transient prose |
| Terminal | render shells, agents, tasks, tmux, and Herdr | `TerminalView` and terminal host | TUI remains authoritative; ownership and failure stay inline |
| cmux | continue in the external Workspace owner | cmux | explicit handoff; no simulated cmux UI or fake attach |
| Files, Search, Git, Diagnostics, Debug | complete the development loop | existing Zed surfaces | ordinary pane tabs with honest loading, empty, failure, and recovery states |
| Settings | expose only working product choices | native Settings store and renderers | Workspace and terminal choices first; no dead rows or internal diagnostics |

## Primary user stories

### Start and focus

1. Open or restore one Workspace.
2. Start the configured terminal, Codex, Claude Code, OpenCode, a native shell,
   or Workspace tmux from Home or the adjacent native `+`.
3. Keep the new destination in the current pane unless the user explicitly
   splits.
4. Show the active Workspace, focused pane, selected tab, and durable status
   without a second toolbar.

### Supervise and return

1. Project only active, running, actionable, recoverable, or review-ready work
   into Activity.
2. Keep idle open content in Layout and completed history in Agent History.
3. Select an Activity or Layout row to focus its existing owner.
4. Preserve the current Main Work Area while browsing or searching Workspaces.

### Inspect and verify

1. Open Files, Search, Diagnostics, Debug, Git, or Review as ordinary tabs.
2. Keep every file and tool reachable after another item opens.
3. Keep errors and recovery inside the owning surface with the failed content
   or terminal output still visible.
4. Never claim a successful check, live process, migration, or ownership
   transfer without authoritative evidence.

## Surface milestones

### 1. Navigation and chrome

- Keep one native tab strip in every real pane and an adjacent `+` after its
  tabs.
- Make selected tabs, focused panes, title-bar controls, Workspaces rows, and
  the status line follow one density, icon, type, contrast, and radius system.
- Collapse secondary metadata before Workspace, pane, actionable Activity, or
  recovery identity at narrow widths.
- Keep Workspaces optional and restore it from the labeled status-bar action.
- Remove duplicated navigation, unexplained panes, hover-only actions, and
  product controls that do not map to an existing owner.

### 2. Home and Settings

- Keep Home concise: open or clone a Workspace, start the configured tool,
  resume running work, inspect Files, and review changes.
- Use inline installation and access states. Never show a setup tour, mascot,
  centered recovery overlay, or background permission loop.
- Order Settings by the product loop: **Workspaces & Terminals**, **Agents**,
  **Appearance**, **Workspace & Privacy**, then inherited editor tools.
- Give each Dez root Settings page one semantic native icon while keeping the
  full page title; nested section rows remain text-only, and the column width
  follows Interface Density rather than clipping the added hierarchy.
- Require a native renderer and resolved default for every curated field.
  Unsupported structured settings remain available through the native
  settings file instead of a broken control.
- Keep Debugger Settings connected to the existing Debug surface and the active
  Workspace `debug.json`; neither action starts a build.

### 3. Terminal, agents, and multiplexers

- Render Codex, Claude Code, OpenCode, Gemini CLI, Aider, and other TUIs as
  native terminal output with only trusted status and recovery around them.
- Launch Claude Code with `claude`; keep `claude --continue` as a distinct
  resume action.
- Keep tmux as the in-Dez Workspace fallback and external process owner.
- Keep Herdr discovery and attach bounded, retryable, and non-destructive.
- Prefer explicit **Open Workspace in cmux** handoff when cmux is available;
  cmux owns its tabs, panes, browser, hooks, and action registry.
- Preserve legacy sessions by default and describe replacement shells as new
  computation.

### 4. Complete native tool loop

- Prove Files, file tabs, Search, tasks, Diagnostics, Outline, Git Changes,
  Git History, diffs, Review, and Debug through the same pane model.
- Keep loading, empty, denied, stale, disconnected, and failed states compact
  and actionable.
- Keep Debug setup, adapter output, console, breakpoints, Retry, and logs in one
  native Debug lifecycle.
- Preserve ordinary Zed-quality editing, language tooling, keyboard behavior,
  Git, and extension compatibility behind explicit Dez product policy.

### 5. Visual and accessibility system

- Validate Lumin Blur, Lumin, and Lumin Light with normal and reduced system
  transparency.
- Use IBM Plex Sans for interface roles and Lilex for code and terminal roles
  while preserving explicit user font choices.
- Validate Compact, Balanced, and Spacious density across title bar, native
  tabs, Workspaces, Settings, terminal context, notifications, and status.
- Pair every semantic color with text or an icon, expose selected and expanded
  state, preserve visible keyboard focus, and keep screen-reader order aligned
  with the visual hierarchy.
- Validate 760x600, 960x720, 1160x760, 1440x900, and full-screen logical
  viewports without clipping, overlap, horizontal navigation scrolling, or an
  accidental permanent column.

### 6. Continuity and release evidence

- Require stable installation before Workspace restoration or durable-terminal
  startup.
- Preflight each Workspace root once before Git, Search, LSP, agent, or
  terminal work begins.
- Preserve eligible host-owned work through normal quit, relaunch, renderer
  failure, and UI detachment without silent process termination.
- Keep source, remote-CI, installed-runtime, visual, accessibility,
  integration, package, signing, and notarization evidence separate.
- Build and package only through GitHub Actions. Stable promotion requires a
  Developer ID signature, notarization, Gatekeeper acceptance, exact source
  identity, and an Apple M2 artifact audit.

## Stop-ship defects

- startup crash, blank window, re-entrant entity access, quit timeout, or lost
  eligible process;
- invisible Workspaces recovery, missing adjacent `+`, hidden focused pane,
  file replacement, duplicate tab ownership, or unexplained split;
- custom tab chrome, floating onboarding, persistent mascot, task bubble,
  custom permission overlay, fake browser, or permanent inspector;
- dead primary action, inaccessible icon, color-only state, clipped public
  copy, `NO RENDERER`, or `NO DEFAULT`;
- repeated protected-folder prompts, access-error flooding, mismatched terminal
  endpoint, duplicate attach, or destructive legacy recovery;
- false agent lifecycle, transcript-derived success, fake migration, or
  incorrect tmux, Herdr, or cmux ownership;
- source/artifact mismatch, wrong architecture, Preview presented as Stable,
  unsigned Stable package, failed notarization, or failed Gatekeeper check.

## Evidence matrix

| Gate | Required evidence |
| --- | --- |
| Source | exact commit, focused diff, format, identity, theme, and source guards |
| Compiled | exact GitHub Actions run and successful focused regressions |
| Runtime | installed exact artifact, cold start, primary loop, failure paths, quit, and relaunch |
| Visual | exact artifact screenshots for themes, transparency, density, and viewport matrix |
| Accessibility | keyboard, focus, labels, expanded state, contrast, truncation, motion, and screen reader |
| Integration | provider and multiplexer versions, discovery, launch or attach, recovery, and ownership result |
| Package | artifact name, checksum, architecture, bundle identity, signature class, and source SHA |
| Release | Developer ID, notarization, Gatekeeper, tag, rollback point, and known limitations |

## Definition of ready

v0.5 is ready only when the exact installed release candidate proves every
primary story, milestone, stop-ship gate, and evidence row above. Source guards
prove policy only. A plausible screenshot, successful compile, or older green
artifact cannot validate a newer commit.

Until builds resume, source-only polish may advance in small reviewable slices,
but the branch remains an unbuilt v0.5 planning candidate rather than a release.

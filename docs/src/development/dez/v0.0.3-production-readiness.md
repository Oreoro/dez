# Dez v0.0.3 production readiness

This is the active execution plan for Dez v0.0.3. It narrows the release to
polishing and proving the product that already exists. [Fork Notes](./fork-notes.md)
remain the permanent product and architecture source of truth and win if this
plan conflicts with them.

The [v0.0.2 Completion Plan](./v0.0.2-completion-plan.md), source ledger, and
installed-build audit remain historical evidence. They do not prove this
candidate and they no longer define execution order.

## Release decision {#release-decision}

v0.0.3 is a hardening release, not a feature expansion. It must make one loop
obvious and dependable:

> Open a Project, run Codex, Claude Code, OpenCode, or another supported agent
> in an Agent Terminal, supervise meaningful agent state under Projects, and
> review the same codebase through Files, Git, diagnostics, diffs, tests, and
> the editor.

The terminal is the default agent execution surface. Built-in Agent remains an
optional provider-backed conversation surface. Projects is navigation and
supervision, not a second terminal or chat transcript. Workspace Tools contains
Files, Outline, Git, and Debug. Files, terminals, settings, search, diagnostics,
diffs, and review stay in the Main Work Area.

Projects, Workspace Tools, and Built-in Agent compete for one optional
auxiliary slot. Opening one hides the other two and preserves the Main Work
Area. No route may reopen an inherited dock, create a blank auxiliary pane,
cover work with a floating surface, or leave focus inside hidden UI.

## Scope {#scope}

v0.0.3 includes:

- startup, crash, restore, and terminal-host reliability;
- the existing Home, Projects, Workspace Tools, Main Work Area, Built-in
  Agent, terminal, Git, diff, diagnostics, settings, and notification surfaces;
- project-to-session navigation and honest Machine Terminal observation;
- the six public Workspace layouts and their focus/resize behavior;
- Lumin Blur and Lumin Light material ownership;
- IBM Plex Sans interface typography, Lilex code and terminal typography, and
  the Dez icon theme;
- keyboard, screen-reader, reduced-transparency, and narrow-window behavior;
- exact-source macOS bundle proof and public-preview packaging.

v0.0.3 does not include:

- embedded Live Preview or browser automation;
- adoption or input control of PTYs owned by another application;
- a Kanban board, task database, automation dashboard, or orchestration
  platform;
- a second structured terminal-agent adapter;
- remote terminal durability or cross-device continuation;
- a new navigation model, new panel category, or another persistent sidebar.

## Evidence vocabulary {#evidence-vocabulary}

Every claim uses one of four labels:

- **Source** — code, settings, documentation, or a static guard exists.
- **Compiled** — the exact candidate commit completed the stated build or test.
- **Runtime** — the exact packaged candidate was observed in the stated
  scenario.
- **Released** — the signed, notarized, checksummed artifact and release notes
  were published.

Source evidence is never promoted to Runtime. A successful build of an older
commit is historical and cannot validate a newer candidate.

## Current checkpoint {#current-checkpoint}

Source currently contains:

- Dez application, bundle, URL-scheme, data-boundary, icon, and default-run
  identity;
- a terminal-first Home and Projects model;
- host-owned packaged local terminal sessions with deliberate end semantics;
- supported terminal-agent detection and an optional Codex structured adapter;
- read-only macOS Machine Terminal discovery;
- one pane grid with one optional auxiliary surface;
- curated Workspace layouts with Main Work Area width guards;
- provider-gated Built-in Agent creation and recovery actions;
- Lumin system appearance, Plex/Lilex defaults, and a reset-to-Dez-appearance
  action;
- source guards for identity, public vocabulary, theme assets, panel
  arbitration, focus, terminal lifecycle, and packaging.

The active candidate is not production-proven. The latest known successful
macOS bundle action built commit
`ead91e2360815b61d0cc75f3fdecb48625d48825`, which predates the current source.
No exact-candidate runtime matrix has been recorded.

- [ ] Launch with migrated legacy data and with corrupted optional layout
      state.
- [ ] Confirm a failed restore produces an actionable recovery state instead of

- [ ] Open an Agent Terminal, run an interactive command, close the GUI

- [ ] Confirm task, remote, and externally owned terminals never inherit a
      durability claim they do not satisfy.

## Milestone 2 — one coherent shell {#milestone-2}

- [ ] Home explains the loop in one sentence and exposes one recommended first
      action.
- [ ] Projects groups real Agent Sessions beneath their Project and keeps
      ordinary shells out of the list.
- [ ] Machine Terminals is visibly read-only and never implies transcript or
      input access.
- [ ] Workspace Tools switches among Files, Outline, Git, and Debug without
      creating another Project or covering work.
- [ ] Built-in Agent replaces the current auxiliary surface and never appears
      beside Projects or Workspace Tools.
- [ ] Protocol, keyboard, command-palette, pointer, restore, and starts-open
      activation routes all use the same auxiliary-surface arbitration.
- [ ] Closing any auxiliary surface returns focus to a visible terminal,
      editor, diff, or review Surface.
- [ ] No public layout manufactures an empty pane or exposes a geometry-only
      feature.

Exit condition: every navigation route preserves one Main Work Area and at most
one auxiliary surface.

## Milestone 4 — Agent and review recovery {#milestone-4}

- [ ] **Open Agent Terminal** is the primary path from Home and Project actions.
- [ ] Starting Codex, Claude Code, or OpenCode promotes the existing terminal
      Session without opening a duplicate Surface.
- [ ] Selecting the Project Session returns to the existing terminal or
      reattaches its Host Session.
- [ ] Built-in Agent creation without a usable provider opens configuration
      and does not create a failed draft.
- [ ] Built-in Agent empty, loading, auth, model, rate-limit, offline, stopped,
      and retry states are actionable and do not cover the composer.
- [ ] Files and Git observe the same Project modified by either agent path.
- [ ] Diff, diagnostics, tests, and Git status remain available when an Agent
      Session needs attention.
- [ ] Session Details distinguishes observed, derived, agent-reported,
      user-confirmed, and unknown evidence.

Exit condition: terminal-agent and optional Built-in Agent paths both return to
the same native review loop without ambiguous ownership.

## Stop-ship defects {#stop-ship-defects}

Any of these blocks v0.0.3:

- startup crash, repeated crash loop, blank restored window, or inaccessible
  recovery action;
- a packaged local terminal dying because the GUI closed unexpectedly;
- a false reattach, Live, managed, or durability claim;
- Projects, Workspace Tools, and Built-in Agent visible side by side;
- inherited dock plus pane-tab duplication;
- Main Work Area below 60% because of an auxiliary surface;
- clipped primary action, vertical tooltip copy, unbounded overlay, double
  header, or focus trapped in hidden UI;
- Lumin Blur rendering opaque black because the material contract failed;
- Built-in Agent creating a failed draft instead of routing to provider setup;
- a version, executable, bundle, URL scheme, storage, icon, or artifact identity
  mismatch;
- documentation claiming Runtime or Released evidence that was not observed on
  the exact candidate.

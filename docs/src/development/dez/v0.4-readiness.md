# Dez v0.4 readiness

This is the active source and exact-artifact contract for Dez 0.4.0. It does
not claim that a signed or notarized v0.4 release has shipped. Older v0.2 and
v0.1 documents preserve the decisions and evidence that produced this lane;
they are not competing release targets.

## Product promise

Dez is a native Workspace for terminal-native development:

```text
open a Workspace
-> run Codex, Claude Code, OpenCode, tmux, Herdr, or a shell in native tabs
-> supervise only actionable work in Workspaces
-> inspect files, Git, diagnostics, and diffs in the Main Work Area
-> recover access or terminal ownership without losing running processes
```

Workspaces identifies the codebase and projects its native tabs, panels, Git
state, and actionable Activity. The Main Work Area owns files, terminals,
Settings, diffs, tools, splits, and tab lifecycle. Terminal applications keep
their own TUI; Dez does not re-render them or pretend to migrate externally
owned processes.

## v0.4 surface contract

- **Home** is a branded native tab, not onboarding or an overlay. It starts
  with Open Workspace, then presents the configured terminal, supported agent
  CLIs, cmux handoff, the tmux fallback, Files, running Sessions, and review in
  workflow order.
- **Workspaces** is optional, collapsible supervision. Its active Workspace
  projects every open native item under **Layout**, omits fake single-pane
  chrome, and names real split panes only. **Activity** contains only current
  authoritative active, running, actionable, recoverable, or review-ready
  signals and disappears when empty; idle open content stays in Layout and
  inactive completed Agent Sessions stay in Agent History. Externally owned
  work is summarized by one **Running Sessions** disclosure. The ordinary
  preview is limited to five top-level rows, including that disclosure, and
  prioritizes the current destination plus attention-required rows; a
  native disclosure reveals the complete current set, while Search and
  Attention scope remain exhaustive. Empty external sections and optional
  integration notices do not occupy navigation space. Stale last-known tmux,
  Herdr, and cmux rows remain reachable in Attention until their source
  refreshes or resolves. An
  explicit **Browse Running Sessions…** request keeps one bounded result visible
  even when no unmatched row exists, distinguishes checking, healthy-empty,
  private, and failed discovery, and keeps disclosure and Retry keyboard
  reachable. **Remove Workspace from Window** selects the nearest healthy
  loaded neighbor, including a retained remote Workspace; it opens only an
  unloaded local neighbor and uses a durable empty Workspace when no reachable
  neighbor remains.
- **Main Work Area** keeps native Back, Forward, adjacent Add, overflow, split,
  zoom, drag, preview, pin, dirty, and close behavior. Files is a reversible
  destination; opening a file does not replace another file by default. A
  fresh Workspace does not open Files automatically, while restored layouts
  and the explicit **Open Files Automatically** preference remain respected.
- **Top Bar and Status Bar** use one density-aware control, icon, and type scale.
  Compact tab controls fit their 24px strip instead of overflowing it, Layout
  rows, the Workspaces title and search rows, and the labeled status-bar
  destination scale with Workspace density. Search, dismiss, Add, split, and
  navigation marks share the selected control and icon scale while remaining
  visually subordinate to content. The status bar remains visible by default,
  respects an explicit user choice, and always offers the Workspaces
  destination. Wide windows name the active Workspace in that button; compact
  windows preserve the same density-scaled icon, tooltip, accessible name,
  attention state, and action without crowding editor or terminal context.
  Balanced Workspaces rows use the same small icon role; selected content uses
  normal foreground color while accent remains reserved for meaningful state.
- **Terminal Details** stays an inline disclosure with compact Status, Agent or
  Process, Path, Git, and Ownership rows. Failed attach and Host states expose
  Retry and actionable diagnostics without opening an overlay, permanent
  inspector, or duplicate terminal renderer. Inline terminal height rounds up
  to a complete device pixel so fractional display scaling cannot clip its first
  output line. tmux and Herdr attach tabs identify the external owner and state
  that the native tab owns only the attach client.
- **Settings** begins with Workspaces & Terminals, Agents, and Appearance.
  Curated fields use native renderers; internal `NO RENDERER` or `NO DEFAULT`
  diagnostics are stop-ship defects. Any Dez field without a native control or
  resolved default falls back to the native settings file rather than
  presenting an internal error as a control.
- **Identity** uses Lumin, IBM Plex Sans for UI, Lilex for code and terminals,
  the Dez icon theme, rounded high-contrast native tabs with medium-weight
  selected labels, and quiet semantic provider marks. Known
  generated legacy profiles migrate narrowly while preserving font sizes,
  panel positions, and unrelated choices.

## Terminal and integration contract

**Open Terminal** launches the configured default. Native Shell, Codex, Claude
Code, and OpenCode stay adjacent in the pane Add menu; Gemini CLI, Aider,
Herdr, and custom commands remain available without crowding the first level.
cmux handoff, running-session discovery, and **Workspace tmux · fallback** share
one named multiplexer group. New Claude terminals run `claude`; resuming the
last Claude Session is a separate `claude --continue` action.

cmux remains an explicit external Workspace handoff. tmux and Herdr attach in a
native terminal without transferring process ownership. Discovery distinguishes
Missing, Empty, Failed, Ready, and Access required. Retry is bounded and never
creates an automatic duplicate attach. Closing an attach tab can stop its local
client, but never claims to stop, migrate, or own the external session.

The generated Terminal Host endpoint is the single source of socket, token,
and generation identity. Legacy processes remain visible as **Legacy · Access
blocked** until the user opens a replacement shell, keeps the process running,
or confirms termination.

## Reliability and access gates

- A temporary, DMG, translocated, or user-local launch shows native Home and
  requires Install and Relaunch before restoration or durable-terminal startup.
- Each Workspace root is preflighted once. A missing grant becomes one native
  Access required state; Git, search, LSP, agent, and terminal work do not flood
  logs behind it.
- Quit cancels active project search and completes promptly with denied roots.
- No render path re-reads the GPUI entity currently being updated.
- A remote Workspace open returns the Workspace it created, even if another
  Workspace becomes active while restored state and toolchains finish loading.
- No running process is silently killed, claimed, or migrated.

## Release ladder

1. Run formatting, identity, shell-syntax, and diff-hygiene checks locally.
   Do not compile Dez locally.
2. Commit and push one exact source candidate.
3. Build, compile, run the focused Workspace-removal, remote-open,
   inline-terminal, tmux, Herdr, and cmux regressions, optimize, package, and
   validate through GitHub Actions.
4. Install the exact Apple M2 artifact side-by-side and run the complete Home,
   Workspace, Files-return, tab, Settings, terminal, access, failure, restart,
   and coexistence audit.
5. Record commit, workflow, artifact, hashes, bundle identity, architecture,
   signature, screenshots, and observed failures in Release Evidence.
6. Preview remains explicitly non-stable. Stable requires a Developer ID
   signature, notarization, and successful Gatekeeper assessment; missing
   credentials fail the workflow.

## Stop-ship defects

- crash, panic, blank window, broken click target, or re-entrant GPUI entity
  access on a primary route;
- invisible status bar, missing adjacent Add, file replacement, duplicate pane,
  unrecoverable Files navigation, or a Workspace item that cannot be focused;
- `NO RENDERER`, `NO DEFAULT`, inherited Zed identity, generated all-monospace UI,
  fake browser chrome, custom overlay onboarding, or non-native permission UI;
- repeated protected-folder prompts, access-error flooding, or a Host endpoint
  mismatch;
- automatic duplicate attach, incorrect Claude resume behavior, unbounded cmux
  or Herdr command, running-session discovery that stays hidden behind a nested
  disclosure, or destructive legacy recovery without confirmation;
- artifact/source mismatch, wrong architecture, failed deep signature check, or
  a Preview presented as Stable.

## Completion evidence

v0.4 is ready only when the exact 0.4.0 candidate proves every stop-ship gate in
the installed artifact. Source checks, a successful compile, and a plausible
screenshot are necessary but not sufficient evidence on their own.

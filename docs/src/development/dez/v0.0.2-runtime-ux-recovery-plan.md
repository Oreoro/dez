# Dez v0.0.2 Runtime UX Recovery Plan

This plan records what the installed Apple-silicon build actually does and
orders the work required before another public preview. It refines
[v0.0.2 Active Plan](./v0.0.2-active-plan.md); it does not replace
[Fork Notes](./fork-notes.md).

## Product decision {#product-decision}

Dez is a terminal-first code review IDE:

> Run work in a terminal, supervise its state in the Session Rail, and inspect
> or change the result with the editor, Files, Search, Git, diffs, diagnostics,
> Debug, and Agent without leaving the Workspace.

The terminal is where computation runs. It is not the whole product. The IDE is
the inspection and intervention layer around that computation.

The release-defining loop is:

```text
Open Workspace
-> Start Terminal Session
-> Run Codex or another long-lived command
-> See one truthful Session Rail row
-> Open changed files, Git, or a Review Brief
-> Inspect or edit in the Main Work Area
-> Return to the same live Terminal Session
```

Agent Sessions are a second way to delegate work through a native conversation.
They are not terminals, and Agent History is not Git history.

understandable workflow.

## Source progress {#source-progress}

The first recovery slice is implemented in source:

- The Dez welcome screen now teaches **Run**, **Supervise**, and **Review** as
  one sequence. **Open Workspace** is primary; a home-directory terminal is
  explicitly **Open Scratch Terminal**.
- Git's ambiguous tabs are now **Git Changes** and **Git History**.
- A terminal is labeled **Persistent** only when an active external terminal
  Host owns its exact saved snapshot. GUI-owned terminals are labeled
  **Workspace Terminal Session**.
- Scratch terminals in an empty Workspace now get a transient Session Rail
  group, so visible computation cannot coexist with **No sessions yet** merely
  because the Workspace has no project path.
- Session Rail now says **Loading sessions** while Workspace restoration or Host
  reconciliation is still pending. Start-fresh actions remain unavailable
  until restoration reaches its ready state. A genuinely empty rail names
  **Open Workspace** as the primary folder-only, same-window route and keeps
  **Open Scratch Terminal** as a secondary pathless option. With a ready
  Workspace but no Sessions, **Start Terminal Session** is the primary action.
  Loading presentation takes precedence over stale attention styling.
- A stale saved Agent Session tab is now omitted as typed recoverable state
  instead of emitting the generic `missing serialized agent thread item`
  failure. Dez shows one persistent recovery notice pointing to Agent History;
  the next Workspace serialization heals the stale layout.
- Every standalone Dez terminal now has a compact context bar driven by
  terminal, Workspace, and Git owners. It shows lifecycle, Workspace/branch,
  and live changed-file count; **Files**, **Review Changes**, and **Session
  Details** provide the direct IDE handoff. Git changes refresh through
  structured Git-store events rather than terminal text parsing.
- The context bar now gives its fixed action group priority at narrow pane
  widths. Lifecycle/repository metadata is the shrinkable, clipped region; its
  full values remain in Session Details instead of painting through Files,
  Review Changes, or Details.
- **Review Changes** is now one Workspace-owned Git action rather than a pair of
  panel toggles. It reveals the bounded Git Changes drawer, selects a concrete
  changed file, and opens the uncommitted diff in the Main Work Area. Repeating
  it cannot close the drawer accidentally; a clean repository stays on the
  explicit Git clean state instead of opening an empty diff.
- The resulting Main Work Area review now identifies its active Surface as
  **Diff · filename**. Its tooltip retains the diff base and relative path;
  official Zed keeps its inherited Project Diff vocabulary.
- **Files** now uses one Workspace-owned, idempotent reveal/focus action across
  Welcome, the active terminal, Session Rail keyboard path, and terminal
  context menu. Repeating the destination action cannot close Files or expose a
  different Workspace Tool.
- When the selected saved Session belongs to a closed Workspace, **Files** now
  reopens that exact Workspace, restores the existing Agent or Terminal
  Session, and only then reveals the project tree. It no longer fails silently
  or creates a substitute Session.
- Terminal rows expose the same Git review and Session Details vocabulary.
- Workspace Tools and Agent panes start at the smaller of 360 px or 22% of
  available horizontal space. Opening, resizing, hiding, restoring, or applying
  a saved layout preserves at least 60% for primary work instead of producing
  equal-width columns. Restored Agent panes retain Agent-region ownership.
- Welcome guidance now adapts to real Workspace state. With no Workspace it
  leads with **Open Workspace** and **Open Scratch Terminal**; inside a
  Workspace it leads with **Start Terminal Session** and **Open Files** instead
  of asking the user to open the Workspace again.
- Welcome now assigns the only filled treatment to that state-dependent first
  action. Secondary choices remain visibly subordinate. Git, Debug, Outline,
  and Agent toolbar controls are keyboard-focusable and specifically named for
  assistive technology; Dez uses Debug and Stop for the debugger's lifecycle
  controls, and its Agent title-edit action remains visible without hover.
- Keyboard focus now reveals the same Workspace-row controls as pointer hover.
  New Terminal and Options remain visible and enter the tab order on a focused
  Workspace. The already-open Workspace menu keeps its scoped close controls
  visible; search clearing and onboarding-banner dismissal are also
  keyboard-focusable.
- Main Work Area Back/Forward, Add, Switch Surface, Split, Zoom, and auxiliary
  Hide controls now enter the keyboard tab order. The active unpinned Dez tab
  keeps Close visible and focusable without making every inactive tab noisy;
  pinned dirty tabs preserve their status indicator.
- Visible Dez terminal tabs use the explicit **Terminal · title** surface
  vocabulary when a meaningful title exists. Official Zed keeps its inherited
  tab labels.
- The primary focus roots observed in the installed audit now have stable
  accessibility nodes in source. Populated and empty Files, Outline, Git
  Changes/History, Debug, Agent, native and external Agent Sessions, Agent
  History, and terminal failure/panel surfaces each combine an element ID,
  semantic role, specific label, and their tracked focus handle. Runtime log
  verification remains required against the rebuilt artifact.
- Lumin Blur and Lumin Light now use bounded whole-window glass layers for the
  shell, rail, editor, terminal, toolbar, tab strip, title bar, and status bar.
  The opaque fallback remains available. Dense overlays preserve readability;
  the guard checks alpha ranges, region separation, and a 1.5:1 structural
  boundary after compositing over dark, neutral, cool, and warm backdrops.
- Lumin interaction feedback now follows a measured hierarchy on those same
  surfaces: hover is visible, active/selected are stronger, scrollbars progress
  from idle to hover to drag, and the active editor line has a non-zero floor.
  The opaque fallback no longer makes active weaker than hover.
- JetBrains Mono now spans interface, editor, terminal, prompt, Markdown, Git,
  and review roles by default, so the product identity is visible throughout
  the native IDE rather than only inside code. The exact old Dez-generated
  `.ZedSans` profile upgrades in memory through the normal backed-up settings
  migration; deliberate custom fonts and official Zed profiles are untouched.
- The actual older generated profile found on the installed machine is also
  recognized. Its exact `.ZedSans` + light mode + One Light signature migrates
  as one unit to JetBrains Mono and system-selected Lumin Light/Lumin Blur.
  Arbitrary custom font/theme profiles remain outside this migration.
- Empty ready Workspaces now present **Start Terminal Session** as their filled
  primary recovery. Once Sessions exist, the overview's **New Terminal**
  becomes an outlined utility so supervision and review remain visually
  primary.
- Terminal-focused Workspace status now keeps healthy Search and diagnostics
  icon-only while retaining keyboard stops, tooltips, and complete accessible
  labels. Error/warning counts and diagnostic messages remain visible.
- Settings and the command palette now expose **Restore Dez Visual Profile**.
  It repairs only Lumin, JetBrains Mono, and built-in Dez icon choices,
  preserves size/non-visual preferences, and confirms after persistence.
- Welcome, Onboarding, Session Rail, and terminal-context actions now share one
  icon grammar: Terminal for computation, Folder Open for Workspace/Files,
  File for creation, Diff for review, Info for Session details, List Tree for
  supervision, Clock for Agent History, and Settings for configuration.
- The built-in file/folder icon theme is product-facing as **Dez (Default)**;
  the original **Zed (Default)** name remains available as a compatibility
  alias.
- After a terminal starts, the welcome explanation collapses into the existing
  **Session Details** disclosure. **How Dez Works** preserves the
  **Run → Supervise → Review** model without adding permanent shell chrome.
- The same disclosure now includes a compact **Evidence** contract: lifecycle
  comes from Terminal/Host state, Git counts remain Workspace-owned, change
  attribution is not inferred, agent confidence/checks require trusted
  evidence, and terminal prose is not proof.
- A Scratch Terminal now exposes **Open Workspace** in that same context strip.
  The action accepts folders only and explicitly opens each selected codebase
  in the current window, so the running computation survives the transition
  and gains Files/Git context. Its collapsed guide says **Connect** until that
  context exists.
- Graceful shutdown now gives concurrent PTY cleanup and session-state writes a
  two-second correctness budget instead of racing all observers against a
  200 ms aggregate deadline.
- Official Zed retains its upstream welcome, Git labels, and terminal wording.

This is source evidence only. The installed `91a1514` artifact predates these
changes.

## Target screen model {#target-screen-model}

Dez keeps three visible layers, not three equal columns:

1. **Session Rail**, 264–288 px by default, is the persistent supervisor.
2. **Main Work Area** always owns most of the window and contains terminal,
   editor, diff, search, settings, and review Surfaces.
3. **Workspace Tools** and **Agent** are contextual drawers. They are closed by
   default, initially bounded to the smaller of 360 px or 22% of available
   width, and never silently reduce the Main Work Area below 60% of the window.

The active Terminal Session gets one compact context strip:

```text
Codex · Running     zed 3.0 / main     5 changes
[Files] [Review Changes] [Session Details]
```

The strip uses authoritative owners:

- the terminal or adapter supplies actor and lifecycle;
- the Workspace supplies repository and branch;
- Git supplies changed-file counts;
- Review Brief discloses what was and was not observed.

It does not parse arbitrary terminal prose into trusted state.

## Ordered implementation {#ordered-implementation}

### Phase 0: restore truth before polish {#phase-0-truth}

1. Make terminal creation publish its Session Rail projection before or in the
   same frame as the terminal Surface. The zero state must not render while a
   visible terminal entry exists.
2. Introduce explicit projection states: **Loading sessions**, populated, and
   truly empty. Do not use **No sessions yet** while restore or host
   reconciliation is pending.
3. Derive durability copy from the active owner:
   - helper-owned and reconnectable: **Persistent**;
   - GUI-owned but retained across tab closure: **Workspace terminal**;
   - saved metadata without a live owner: **Saved** or **Unavailable**.
4. Fix the `app_will_quit` timeout before claiming GUI-independent process
   survival.
5. Repair the missing serialized Agent Session restoration path. A stale record
   must become an explicit unavailable row or be omitted with a recovery notice;
   it must not fail invisibly.
6. Add IDs and roles to every focusable region observed in the runtime log.
   Repeated missing-accessibility-node logs fail the gate.

Primary source owners:

- `sidebar::Sidebar`
- `agent_ui::TerminalThreadMetadataStore`
- `terminal::session_host`
- `workspace::persistence`
- `workspace::MultiWorkspace`

### Phase 1: teach the product in one screen {#phase-1-teach}

Replace the generic welcome action list with a progressive start state.

With no Workspace:

- primary: **Open Workspace**
- secondary: **Clone Repository**
- tertiary: **Open Scratch Terminal**
- explanation: “Open a codebase, run work in a Terminal Session, then review
  its changes here.”

With a Workspace and no Session:

- primary: **Start Terminal Session**
- secondary: **Open Files**
- a three-step guide: **Run**, **Supervise**, **Review**

After the first terminal starts, collapse the guide into a small
**How Dez works** action. Do not permanently consume vertical space.

Primary source owners:

- `workspace::welcome`
- `sidebar::Sidebar`
- first-run settings and persisted onboarding state

### Phase 2: connect the terminal to the IDE {#phase-2-connect}

1. Add the active Session context strip above a detected terminal.
2. Add **Review Changes** when Git reports changes. It opens the Git change list
   and the selected diff in the Main Work Area; it does not merely reveal a
   separate oversized tool column.
3. Add **Files** and **Session Details** beside review. **Session Details**
   contains lifecycle, working directory, Host/Session identity, adapter
   confidence, and explicit setup limitations.
4. Make each Session Rail row expose the same actions through pointer, keyboard,
   context menu, and Command Palette.
5. Keep the terminal one shortcut away while reviewing. Returning must focus the
   existing Surface, never create a duplicate.

Primary source owners:

- `terminal_view::TerminalView`
- `sidebar::Sidebar`
- `git_ui::GitPanel`
- `workspace::Workspace`
- `agent_ui::RunReviewBrief`

### Phase 3: constrain layout and vocabulary {#phase-3-layout}

1. Keep the Session Rail at its compact default unless the user resizes it.
2. Start Workspace Tools and Agent at 360 px or 22% of available width,
   whichever is smaller. Preserve at least 60% for the Main Work Area after
   opening, resizing, hiding, layout recipes, and saved-layout restoration.
3. Restore the previous Main Work Area width when a tool closes.
4. Name tool tabs with their owner:
   - **Git Changes**
   - **Git History**
   - **Agent History**
   - **Files**
   - **Outline**
   - **Debug**
5. Make the active Surface title explicit: **Terminal · Codex**, **Diff ·
   PLAN.md**, or **Editor · file**. Avoid a path-only terminal header.
6. Remove duplicate bottom utility rows. Search and diagnostics belong to the
   Workspace status strip; Agent History and Workspaces belong to the Session
   Rail.

Primary source owners:

- `workspace::PanelItem` and pane sizing
- `git_ui`
- `sidebar`
- `title_bar`
- `status_bar`

### Phase 4: visual and input quality {#phase-4-visual-input}

1. Give Lumin Light and Lumin Blur a visible hierarchy for window background,
   rail, drawer, Main Work Area, tab strip, selection, hover, and focus.
2. Use a 1 px neutral structural boundary with at least 1.5:1 contrast between
   adjacent regions. Reserve the stronger 3:1 non-text floor for focus,
   selection, and interactive state—not every divider.
3. Keep UI labels at the shared readable token. Do not introduce more bespoke
   10–12 px metadata.
4. Test terminal colors independently from surrounding chrome. Dez does not own
   or remove the Codex TUI mascot; it supplies enough surrounding identity that
   terminal content cannot be mistaken for application chrome.
5. Preserve one obvious focus ring and one active Surface. Pointer hover must
   never silently activate another Session.
6. Verify every visible action enters the tab order, has a specific accessible
   name, and reports pressed/open state where relevant.

Source token checks enforce hover at 1.18:1, active/selected at 1.3:1, scrollbar
idle/hover/drag at 1.3/1.6/1.9:1, and an active-line floor of 1.09:1 against
their composited surfaces. These are differentiation floors, not text-contrast
substitutes.

### Phase 5: install and restart confidence {#phase-5-install}

1. Make the DMG teach **Drag to Applications**, **Open the installed copy**, and
   **Eject Dez**.
2. When launched from a read-only mounted volume, show one move-to-Applications
   flow before restoring work.
3. Record the running bundle path in diagnostics.
4. Run the exact hero workflow with the external terminal Host enabled and prove
   the shell and foreground process survive GUI exit.
5. If that proof fails, ship without the **Persistent** label and describe
   terminal lifetime honestly.

## Acceptance matrix {#acceptance-matrix}

The next installed artifact does not pass on screenshots alone.

| Scenario              | Required result                                                                                      |
| --------------------- | ---------------------------------------------------------------------------------------------------- |
| First launch from DMG | One install path; no ambiguous parallel running copy.                                                |
| Empty app             | **Open Workspace** is primary and the three-step loop is visible.                                    |
| Start terminal        | A Session Rail row exists no later than the terminal's first visible frame.                          |
| Start Codex           | The row and context strip identify Codex only at the available confidence level.                     |
| Five Git changes      | **Review Changes** opens the change list and a diff without hiding most of the terminal/editor area. |
| Keyboard-only         | Start, select, review, return, rename, detach, and close work with visible focus.                    |
| Accessibility         | No focused control lacks an accessibility node or role; regions and list position are announced.     |
| Close and reopen      | The same process and history return only when helper ownership is active and verified.               |
| Helper unavailable    | The UI says unavailable or workspace-owned; it never says persistent.                                |
| Compact/default/wide  | Main Work Area retains at least 60%; no controls overlap or clip.                                    |
| Lumin Light/Blur      | Region boundaries, text, selection, and focus meet their contrast floors.                            |
| Install cleanup       | The installed app is running and the DMG can be ejected without breaking bundled helpers.            |

Evidence must be captured at four levels:

- source assertions and identity guards;
- focused compilation and tests;
- screenshots plus accessibility trees from the exact artifact;
- restart/process evidence from the installed application.

## Explicit non-goals {#non-goals}

- Do not build a new terminal emulator, Git database, or editor.
- Do not add a dashboard of guessed token counts, costs, or agent state.
- Do not treat raw terminal output as authoritative evidence.
- Do not add more permanent sidebars or global chrome rows.
- Do not expand into remote orchestration before the local run, review, and
  restart loop passes.
- Do not polish false persistence or broken restoration states.

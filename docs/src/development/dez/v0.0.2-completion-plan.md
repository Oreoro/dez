# Dez v0.0.2 completion plan

This is the authority for the work remaining before Dez v0.0.2 can ship. It
replaces the execution order in the accumulated
[v0.0.2 Active Plan](./v0.0.2-active-plan.md) and
[Runtime UX Recovery Plan](./v0.0.2-runtime-ux-recovery-plan.md). Those
documents remain evidence and design history. [Fork Notes](./fork-notes.md)
remain the permanent source of truth and win if this plan conflicts with them.

This plan was created from a documentation and source audit on 2026-07-27. The
repository was on `main` at `988298b903a4353f4ce008a55d1ddd9a46bcbf75`,
matching `origin/main`, with uncommitted product and documentation changes.
The local `upstream/main` reference was 755 commits behind `HEAD`, but had not
been refreshed during the audit. Those values describe the audit input, not a
release candidate.

## Release decision {#release-decision}

v0.0.2 must make one workflow dependable:

> Open a Workspace, run a supported coding agent in an integrated terminal,
> supervise that same terminal through Agent Sessions, and review its changes
> with
> the editor, Files, Search, Git, diffs, diagnostics, and tests.

The terminal owns the process. Agent Sessions is a filtered projection of
meaningful integrated terminal and agent work. The Main Work Area owns
terminals, editors, diffs, and review. Workspace Tools and Built-in Agent may
temporarily use the one auxiliary slot, but they may not replace or cover the
Main Work Area.

On macOS, Agent Sessions may also show an ephemeral **On This Mac** projection
of current-user terminal TTYs owned by another application. These rows are
read-only observations: Dez may show the TTY, foreground executable, owning
application, current directory when available, and a supported-agent hint. It
may reveal the owning application, but it does not own the PTY, accept input,
read the transcript, restore the process, or claim that work as a managed Dez
Session.

The release does not promise:

- adoption or control of terminals owned by Terminal.app, iTerm, Warp, tmux,
  or another application;
- survival of a PTY after Dez itself exits or crashes;
- remote terminal Hosts or cross-device continuation;
- multi-agent orchestration, conflict prediction, or a Kanban system;
- exact attribution of every modified file to an agent;
- a second structured terminal-agent adapter.

Those remain valid long-range work. They are not v0.0.2 release blockers and
must not be implied by labels such as **Persistent**, **Captured**, or
**Durable**.

## Evidence vocabulary {#evidence-vocabulary}

Every completion claim must use one of these labels:

- **Source:** implemented and inspected in the current tree.
- **Compiled:** the relevant current target compiled successfully.
- **Runtime:** exercised in the exact candidate with recorded observations.
- **Released:** present in the signed, notarized, checksummed artifact.

Source evidence never upgrades itself to runtime evidence. Evidence from an
older installed build never validates a newer source tree.

### Milestone 2: make the terminal dependable {#milestone-2}

- [ ] Launch the exact Apple-silicon candidate from its recorded process path.
- [ ] Open a Workspace and an integrated terminal without a crash.
- [ ] Type, paste, select, resize, split, close, and reopen a terminal.
- [ ] Quit normally and confirm there are no `app_will_quit` timeouts or crash
      reports.
- [ ] Reopen Dez and represent unsupported terminal restoration honestly,

- [ ] Confirm a missing saved terminal remains a removable or retryable

- [ ] Exercise an empty Workspace and a restored Workspace separately.
- [ ] Record logs for every crash or timeout and fix the root cause before
      continuing.

### Milestone 3: prove the release-defining loop {#milestone-3}

Use at least Codex as the reference agent.

- [ ] Open a real repository.
- [ ] Start one integrated terminal from the Main Work Area.
- [ ] Confirm an ordinary shell does not appear as agent work in Agent
      Sessions.
- [ ] Run Codex in that terminal.
- [ ] Confirm the existing terminal is promoted to exactly one Agent Sessions
      row.
- [ ] Select the row and return to the same interactive terminal surface.
- [ ] Confirm a quiet full-screen TUI remains detected without output polling
      storms or duplicate rows.
- [ ] Make a small file change through the agent.
- [ ] Inspect the file, Git status, and diff in the same Workspace.
- [ ] Return to the same terminal and continue interacting with the agent.
- [ ] Exit the agent and confirm the row returns to shell state or leaves the
      agent filter according to the documented rule.
- [ ] Repeat with two terminals in one Workspace and one terminal in a second
      Workspace.
- [ ] Exercise running, attention, completed, failed, restoring, and missing
      states without unsupported inference.
- [ ] Confirm search, scope, selection, removal, and attention counts remain
      coherent after state changes.
- [ ] Open terminals in Terminal.app and at least one other supported terminal
      application or IDE.
- [ ] Confirm every current-user external TTY appears exactly once under
      **On This Mac** within one refresh interval.
- [ ] Confirm a supported agent can add an actor hint without promoting the
      external row to managed, interactive, persistent, or attributable work.
- [ ] Select an external row and confirm Dez only reveals the owning
      application; it must not intercept input or manufacture a Dez terminal.
- [ ] Close the external terminal and confirm its row disappears without
      leaving recovery or persistence state.
- [ ] Confirm terminals owned by Dez and `dez-terminal-host` never duplicate
      themselves under **On This Mac**.

Exit criterion: a new user can complete the loop without knowing Dez internals,
and every Agent Sessions row maps to one real, reachable surface.

## Release blockers {#release-blockers}

The release is blocked by any of the following:

- a terminal open, input, resize, close, quit, or reopen crash;
- an Agent Sessions row that cannot reach its owning surface;
- duplicate, stale, or false agent rows;
- a current-user external TTY that is missing, duplicated, persisted after
  exit, or presented as controlled by Dez;
- an ordinary shell presented as supervised agent work;
- UI overlap, clipping, or a hidden recovery action at a supported size;
- a layout that allows Agent Sessions, Workspace Tools, and Built-in Agent to
  compete simultaneously for persistent columns;
- an accessibility focus target without a meaningful role or name;
- unrequested default-workflow network traffic that has no documented reason;
- bundle identity or storage collision with official Zed;
- a candidate whose source commit, build, signature, or checksum is unknown;
- public copy that promises external capture or crash-surviving terminals.

## Deferred backlog {#deferred-backlog}

After v0.0.2, re-plan these as separate vertical slices with their own runtime
proof:

1. default terminal Host ownership and crash-surviving PTY reattachment;
2. deliberate adoption or control of tmux and external terminal work;
3. remote Hosts and cross-device continuation;
4. durable App Session ownership across windows and restarts;
5. structured attention, review, and modified-file evidence;
6. a second supported terminal-agent adapter;
7. multi-agent orchestration, handoffs, conflict radar, and MCP-native work;
8. broader Zed upstream parity after each release checkpoint.

Deferral is not deletion. None of these items may silently re-enter the v0.0.2
release gate without a Fork Notes decision that changes the release promise.

## Definition of done {#definition-of-done}

v0.0.2 is complete only when:

- the exact source commit and current upstream relationship are recorded;
- required formatting, compilation, focused tests, and clippy checks pass;
- normal integrated terminal use is crash-free in the exact candidate;
- the run, supervise, review loop works with one terminal identity and no
  duplicate Session;
- current-user machine terminals are shown as truthful, ephemeral observations
  with no duplicate Dez-owned rows or implied control;
- responsive, glass, typography, icon, input, and accessibility matrices pass;
- local-first startup and official-Zed coexistence are directly verified;
- the public artifact is signed, notarized, checksummed, installable, and
  traceable to its source;
- Release Evidence contains the proof; and
- public documentation states both the workflow and its limitations plainly.

# Dez v0.1 product-hardening plan

This is the preserved execution and evidence plan for the v0.1.0 source
candidate. The active source-polish lane is
[v0.2 Workspace Polish](./v0.2-workspace-polish.md). [Fork
Notes](./fork-notes.md) remain the permanent product and architecture source
of truth.

This document is a release contract, not a claim that v0.1 has shipped. Every
checked item requires source, compiled, runtime, visual, accessibility, or
packaging evidence for the exact checkpoint it names.

## Release promise

> Open a codebase, run a human or coding-agent workflow in a durable native
> terminal, understand what needs attention, inspect the resulting code and
> Git state, and resume after an app restart without reconstructing context.

Dez is a complete native IDE with a terminal-agent supervision wedge. It is not
a terminal dashboard with an editor attached, a chat client with a file tree,
or a second multiplexer UI.

## Product contract

The application has four concepts and one primary path:

| Concept | User-visible job |
| --- | --- |
| **Home** | Open or clone a codebase and explain the product in one screen |
| **Projects** | Optionally switch codebases and supervise only associated Sessions and attention |
| **Main Work Area** | Own native files, terminals, agents, diffs, diagnostics, settings, and review tabs |
| **Workspace tools** | Reveal Files, Outline, Git, Debug, or Built-in Agent through the native tab/pane model |

```text
open Project
-> run in native Terminal or Built-in Agent
-> supervise meaningful state in optional Projects
-> inspect Files, Git, diagnostics, diff, and review
-> close and reopen Dez without losing host-owned work
```

Projects starts closed in a fresh window. It is a native Zed sidebar container
with a Dez-specific projection over real Workspaces, TerminalViews, Agent
Surfaces, and durable Host Sessions. It never renders a terminal, owns a
transcript, duplicates a pane tab, or becomes mandatory navigation.

## Non-negotiable interface rules

- Use one native pane grid and its existing draggable, reorderable, closeable,
  preview-replacing, pinnable, and splittable tabs.
- Put the active task in the Main Work Area. Do not replace it with a dashboard,
  giant onboarding card, or permanent terminal inventory.
- Keep Projects optional and workspace-scoped. Selecting a row returns to the
  existing owning Surface.
- Open Files, Git, Outline, Debug, Built-in Agent, terminal, settings, search,
  and review through registered native surfaces. Do not nest them inside
  Projects or invent another tab strip.
- Use one direct action per common job. Put layout recipes, migration tools, and
  diagnostics behind commands or settings instead of project-row menus.
- Never use a floating mascot, task bubble, screen-edge control, or persistent
  toast as product navigation.
- Prefer semantic icons from the native icon set. Text is a fallback, not an
  excuse for duplicate glyphs or ambiguous buttons.
- Preserve user font settings. Defaults must be readable and neutral in both
  UI and code roles.
- Lumin transparency belongs to window chrome and structural surfaces. Editor,
  diff, terminal, and dense data content retain sufficient contrast.

## Release ladder

Each checkpoint is independently buildable and reversible. A later checkpoint
does not erase an earlier release gate.

### v0.0.4 — truthful ownership baseline

- [x] Use native TerminalView for interactive terminal rendering and input.
- [x] Keep packaged local interactive processes under `dez-terminal-host`.
- [x] Discover tmux, Herdr, and cmux through documented interfaces without
      takeover.
- [x] Keep unrelated machine PTYs outside Projects.
- [x] Make Projects an on-demand supervisor in fresh windows.
- [x] Route Files, Git, Debug, and Built-in Agent to registered native surfaces.
- [ ] Pass the exact macOS build, package, and cold-start artifact gate.
- [ ] Capture the exact dark/light/reduced-transparency viewport evidence.

### v0.0.5 — product clarity and navigation

- [ ] Reduce Home to one primary open action, one secondary clone action,
      recent codebases, and a concise Run -> Supervise -> Review explanation.
- [ ] Make Project, Session, attention, and detached/recovery rows visually and
      semantically distinct without adding dense badges.
- [x] Keep Workspaces as the first-level hierarchy and nest path-matched native
      and external terminal/agent activity beneath its owning Workspace.
- [x] Replace the expanded empty-Workspace onboarding block with one compact
      native terminal action in the Workspace header.
- [ ] Verify pane `+`, tab close, preview replacement, drag/reorder,
      cross-pane move, split, Back, and Forward for every public Surface.
- [ ] Remove dead, duplicate, inherited, and non-functional Dez commands from
      visible menus while retaining compatible Zed functionality.
- [ ] Ensure the Main Work Area remains useful with Projects hidden.

### v0.0.6 — durable lifecycle and crash hardening

- [ ] Prove the same host-owned terminal process survives ordinary quit,
      window close, renderer failure, and relaunch.
- [ ] Distinguish detach, close view, end process, archive, missing,
      incompatible, reconnecting, exited, and failed states.
- [ ] Restore Workspaces, pane tabs, active focus, Projects visibility, terminal
      attachment, and bounded replay without spawning a replacement shell.
- [ ] Exercise corrupt state, missing helper, stale socket, invalid adapter,
      absent provider, and partial migration paths without startup crashes.
- [ ] Add bounded diagnostics for every recovery failure without leaking
      terminal contents or secrets.

### v0.0.7 — agent and multiplexer integrations

- [ ] Detect Codex, Claude Code, and OpenCode from conservative process and
      structured-adapter evidence.
- [ ] Normalize provider, Running, Waiting, Needs Input, Permission, Completed,
      Failed, Reconnecting, and Unknown states without pretending unsupported
      detail exists.
- [ ] Keep the terminal TUI authoritative; Projects shows only status,
      attention, recency, evidence availability, and a return route.
- [ ] Prove deliberate tmux and Herdr attach/detach and cmux Workspace opening
      while the external owner remains alive.
- [ ] Make provider setup capability-aware and prevent empty/dead Built-in
      Agent drafts.
- [ ] Document the adapter trust boundary, retention limits, opt-in behavior,
      and unsupported cases.

### v0.0.8 — visual system, responsiveness, and accessibility

- [x] Replace centered Main Work Area onboarding with compact native empty-pane
      chrome and direct terminal/file actions.
- [x] Keep the editor status bar visible in the Dez profile with active-file
      and line-ending context alongside native diagnostics/language controls.
- [ ] Verify Home, Projects, Terminal, Files, Git, Debug, Built-in Agent,
      Settings, dialogs, menus, and recovery states in dark and light modes.
- [ ] Verify Lumin Blur and Lumin Light with system transparency enabled and

- [ ] Test 760x600, 960x720, 1160x760, 1440x900, and full-screen logical

      or unusable minimum widths.
- [ ] Establish consistent type scale, density, icon size, row height, corner
      radius, separator, hover, selection, focus, and semantic-status tokens.
- [ ] Pass keyboard-only navigation, visible focus, screen-reader naming,

### v0.0.9 — release candidate

- [ ] Rehearse the current upstream Zed merge and classify every conflict.
- [ ] Pass format, identity, theme, source, unit, integration, startup,
      recovery, adapter, accessibility, packaging, and coexistence gates.
- [ ] Build and smoke-test the exact pushed commit on supported macOS hardware.
- [ ] Record artifact checksum, architecture, bundle identity, signing state,
      source SHA, toolchain, rollback, and known limitations.
- [ ] Complete a clean-profile first-run test and an upgraded-profile migration
      test without manual state deletion.

### v0.1 — public-quality checkpoint

- [ ] A first-time user can explain the product after Home and complete the
      primary workflow without documentation.
- [ ] A terminal-native user can use Codex, Claude Code, or OpenCode without
      losing the native TUI, terminal ownership, editor, Git, or debugger.
- [ ] Projects answers “which codebase or Session needs me?” without competing
      with tmux, Herdr, Files, or the Main Work Area.
- [ ] Ordinary editing, language tooling, search, tasks, Git, diagnostics, and
      debugging remain Zed-quality and upstream-maintainable.
- [ ] No known startup crash, destructive recovery path, duplicate process,
      clipped public control, unexplained overlay, or dead primary action
      remains.
- [ ] The exact release artifact passes the documented runtime and visual
      matrix and is promoted from its verified source checkpoint.

## Backend gates

The GUI may project state but cannot become its owner. v0.1 backend work must
preserve:

1. stable App Session, Workspace, Host, Session, Surface, Actor, and Run IDs;
2. process ownership outside the GUI for eligible packaged local terminals;
3. authenticated, versioned, bounded terminal-host protocol messages;
4. explicit ownership for Dez, tmux, Herdr, remote, task, and external PTYs;
5. idempotent restore and attach operations;
6. bounded replay, activity, logs, and adapter evidence;
7. no automatic destructive migration or replacement computation; and
8. evidence labels that distinguish observed, derived, reported, confirmed,
   and unknown facts.

## Integration policy

Integrations earn a public surface only when they preserve ownership and have a
runtime test:

- **Native Zed capabilities:** inherit and adapt before reimplementing.
- **Codex, Claude Code, OpenCode:** terminal-first, optional structured
  lifecycle adapters, no transcript scraping.
- **tmux and Herdr:** explicit project-scoped attachment, never silent takeover.
- **cmux:** project-scoped Workspace discovery and external opening through its
  public CLI; no fake attachment terminal or duplicated layout.
- **Git and language tooling:** native Project-backed stores remain
  authoritative.
- **Built-in Agent/ACP:** optional native conversation Surface, never a
  replacement for terminal agents.
- **Live Preview:** conditional post-core slice. It ships only as a restorable
  pane Surface with native navigation, clear dev-server ownership, and scoped
  permissions; otherwise URLs continue to open externally.
- **Remote and MCP coordination:** deferred until local lifecycle and evidence
  gates pass; any tool must be scoped, revocable, audited, and idempotent.

## Continuous evidence ledger

For every candidate, append rather than overwrite:

| Evidence class | Required proof |
| --- | --- |
| Source | Commit SHA, diff scope, format/identity/theme guards |
| Compiled | Exact workflow run, toolchain, target, and successful jobs |
| Runtime | Cold start, common actions, failure paths, and quit/reopen |
| Visual | Appearance/viewport matrix with exact artifact |
| Accessibility | Keyboard, focus, naming, contrast, motion, and truncation |
| Integration | Provider/multiplexer versions, ownership, attach/detach result |
| Package | Artifact name, checksum, architecture, bundle/signing identity |
| Release | Tag, rollback point, known limitations, and promotion decision |

## Explicitly outside the v0.1 critical path

- a custom pane grid or browser-style tab implementation;
- a second terminal renderer, transcript database, or multiplexer;
- arbitrary PTY adoption or control;
- chat-first Home, Kanban, automation dashboard, or team task system;
- remote orchestration before the local lifecycle is proven;
- broad account, billing, collaboration, or cloud surfaces; and
- visual effects that reduce terminal, editor, diff, or accessibility quality.
